Open: ./bin/btc-miner files
Build: .venv/bin/python -B scripts/build.py

Each moved file has one editable source under src/ or math-library/. The old
btcminer/ package and native/ source paths contain identical compatibility copies.
These retain existing imports, commands, lazy imports in running processes and
historical evidence references. Edit the new source path, not a second copy.
Older private workspaces may use relative links instead; the build gate
requires them to match their canonical sources byte for byte.

Native binaries remain in native/ so loaded-library paths and rebuild commands
stay stable. The explicit /provider command integrates the remote Thesis API;
it is separate from mining workers. No CUDA/OpenCL backend is implemented.
Pool and solo/Core share the pool/ protocol layer.
The mathematics is not duplicated inside the miner folders.

The project browser opens the actual math-library/ and src/ folders side by side.
Root remains available for archives, commands, configuration and compatibility
paths. Every indexed file remains searchable. Local settings are not embedded.

Machine-readable migration map: docs/project-layout.json
Historical audit snapshots remain unchanged. A file move preserves its bytes,
but current source identity and live-process validation are separate facts.
